Vision

What is MeyvnAI?

MeyvnAI is a custom small language model purpose-built for creative writing assistance inside Scriptorium. Where general-purpose models are trained on everything, MeyvnAI is trained on fiction, lore, and dialogue — the craft materials of narrative writing.

The core design principle is offline-first: every component runs on the user's device. No API calls, no cloud dependency, no account required. The int4 ONNX export at ~50 MB is small enough to cache via the browser Cache API and accelerate in WebGPU.

Wrapped around the base transformer is the Digital Biology stack — seven modules that give MeyvnAI biologically inspired training dynamics, emotional awareness, and a persistent memory of who each user is as a writer.

Base Architecture

Transformer Specification

Decoder-only causal transformer (GPT-style) with RoPE positional encoding, SwiGLU activations, pre-norm RMSNorm, and an optional BitLinear 1.58-bit quantization path. The LM head is weight-tied to the token embedding table.

Digital Biology Stack

Seven Biological Modules

Layered on top of the base transformer, these modules introduce biologically inspired training dynamics, inference-time creativity control, emotional intelligence, and persistent user understanding — without adding significant parameter count.

MODULE 01
Elastic Stability
BitLinear v2
ElasticBitLinear

Extends BitLinear with a momentum-based γ EMA to prevent bulk weight-flips across training steps, homeostatic τ scaling to keep the ternary {−1, 0, +1} weight distribution balanced, and an addition-only inner product — no floating-point multiplications in the forward pass.

MODULE 02
Neuromorphic
Spiking Algorithm
SpikingFFN LIFStateless LIFStateful

Leaky Integrate-and-Fire activations wrap the FFN layers. Only the top 5% of neurons fire per token — natural temporal sparsity mirroring cortical firing patterns. Each position receives a sparse activation vector, dramatically reducing the effective computation per token.

MODULE 03
Neuro-Plastic
Optimizer
NeuroPlasticOptimizer

AdamW extended with per-neuron Frequency-Intensity Weight adaptive learning rates. Hyperactive neurons (strong, frequent gradients) are dampened; underused neurons are rescued with a boosted rate. Biologically equivalent to synaptic scaling — only ~10 MB of additional state for the full model.

MODULE 04
Creativity &
Permission
StochasticDivergenceGovernor

A continuous creativity dial: creativity=0 is near-greedy calculation mode (highest-probability continuation); creativity=1 is maximum emotional resonance discovery mode. Four mechanisms govern the dial — temperature interpolation, resonance bonus on self-information, anti-mode penalty, and entropy momentum correction.

MODULE 05
Token Compression
& Addition Kernel
TokenCompressor21 ActivationQuantizer AddOnlyOps

Gated 2-to-1 adjacent-token merging reduces attention FLOPs by 4×. Activation quantizer supports 8-bit and 4-bit (two nibbles packed per int8 byte). The addition-only kernel decomposes ternary weights into binary {0,1} masks and replaces all multiplications with conditional additions.

MODULE 06
Emotion Engine
EmotionEngine EmotionState EmotionalMemory EmpathyModulator

Detects the user's emotional state across three dimensions — Valence (negative ↔ positive), Arousal (calm ↔ excited), Dominance (overwhelmed ↔ in-control) — using a built-in 130-word lexicon plus a learned hidden-state projection. Tracks the session arc via EMA memory with escalation detection. Modulates creativity, empathy warmth, and temperature in response: distressed writers get structure and warmth; excited writers get expansion and energy-matching.

MODULE 07
DNA Memory
DNAMemory Trait

A persistent, observation-driven user profile that accumulates across every session. Seven categories — topics, style preferences, creative triggers, sensitivities, emotional patterns, vocabulary, and session metadata. Each trait carries an EMA strength score that grows with repeated evidence (decay half-life ~4 sessions if unconfirmed; auto-pruned below 5%). On each generation pass, the top-K traits per category are formatted into a [DNA] context prefix that conditions the model on who this specific user is as a writer — no fine-tuning required. Fully serialisable to JSON for browser IndexedDB storage alongside the user's book data. Entirely on-device; nothing is sent to any server.

Roadmap

Development Phases

Week 1–2
Phase 1 — Architecture & Tokenizer
MeyvnSLM PyTorch implementation with RoPE, SwiGLU, RMSNorm, BitLinear. BPE tokenizer at 32,768 vocab with writing-specific special tokens: <|scene|>, <|lore|>, <|inst|>.
Week 3–4
Phase 2 — Data Pipeline
2.5B token corpus assembly. MinHash LSH deduplication, perplexity filtering, language detection, structural token formatting. Memory-mapped uint16 shards for fast DataLoader.
Week 5
Phase 3 — Pre-Training
19,073 steps at 131k tokens/step. M5 Max on-device (~3.6 days, $0) or A100 cloud (~14 hours, <$25). Cosine LR schedule, AdamW β=(0.9, 0.95), grad clip 1.0. WandB logging, checkpoints every 500 steps.
Week 6
Phase 4 — Instruction Fine-Tuning
50k instruction pairs: scene continuation, style matching, lore-grounded generation, outline expansion, lore sentinel detection. SFT with response-only loss masking. M5 Pro or M5 Max.
Week 7
Phase 5 — Export & Quantisation
ONNX int4 (~50 MB) for browser delivery, GGUF Q4_K_M (~56 MB) for Ollama. Validate outputs within 1e-3 tolerance of PyTorch reference. Package as HuggingFace-compatible model directory.
Week 8–10
Phase 6 — Scriptorium Integration
MeyvnModelService.ts streaming token generation via WebGPU. Model download + Cache API caching with progress UI. DNA Memory persistence in IndexedDB alongside book data. Ollama fallback provider.
